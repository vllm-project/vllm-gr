# W1.2 — vLLM-GR Monkey Patch 与私有上游 API 盘点

> Parent RFC: JiusiServe/vllm-gr#157  
> Work package: JiusiServe/vllm-gr#168  
> Task: W1.2 — Inventory all monkey patches and private upstream API dependencies

## 1. 目的

本文档盘点当前 `vllm-gr` 对 vLLM、vLLM-Ascend 和 LMCache 的运行时修改，以及这些修改依赖的公开扩展 API、内部生命周期、私有字段和跨进程协议。

本任务只建立事实基线，不调整生产代码，不改变 Beam Search、Scheduler、ModelRunner、Attention、Catalog 或 OpenAI Serving 的现有行为。

该基线用于：

- 判断每个 Patch 是否仍然必要；
- 明确 Patch 在什么进程、平台和功能条件下安装；
- 识别普通非 Beam 请求受到的全局影响；
- 在上游版本升级时快速定位兼容风险；
- 为 W2–W7 的收窄、替换和移除提供验收依据；
- 为 W1.3 的机器可读 Inventory 和 Contract Gate 提供事实来源。

## 3. Patch 单元定义

本文不按每一次赋值统计 Patch，而按“能够独立安装、验证、失败或移除的一组行为扩展”统计。

例如 GPU ModelRunner 的以下三个替换属于同一个 Patch 单元：

```python
GPUModelRunner.execute_model = patched_execute_model
GPUModelRunner._prepare_inputs = patched_prepare_inputs
GPUModelRunner._bookkeeping_sync = patched_bookkeeping_sync
```

它们一起安装、共同服务 grouped-beam execution，并且必须由同一个 GPU ModelRunner Adapter 替代。

## 4. 总体结论

当前基线可归纳为：

- 1 个运行时激活边界；
- 14 个生产运行时 Patch 或全局修改单元；
- 1 个 Benchmark-only Patch 集合；
- 6 类上游 API 与内部状态依赖边界。

风险最高的是：

1. `EngineCoreRequestType` 运行时 Enum 扩展；
2. `EngineCoreProc.process_input_sockets` 和进程入口替换；
3. `Scheduler.schedule` 替换；
4. GPU/NPU ModelRunner 私有热路径替换；
5. EngineCore Client 和 DP 内部路由状态；
6. LMCache 内部生命周期方法替换。

## 5. 风险分级

| 级别 | 定义 |
|---|---|
| Critical | 影响跨进程协议、请求完成、调度、KV Cache、ModelRunner 热路径，或可能导致请求永久等待 |
| High | 影响全局构造、配置、平台选择、普通请求行为或关键初始化顺序 |
| Medium | 局部行为覆盖，但依赖上游类结构或全局注册，升级时可能失效 |
| Low | 辅助能力，影响范围窄且失败容易定位 |

## 6. 生产运行时 Patch Inventory

### P00 — vLLM General Plugin Runtime Activation

- ID: `GR-PATCH-000`
- Source: `vllm_gr/plugin.py`
- Entry: `vllm_gr.plugin:register`
- Process roles: Main、EngineCore subprocess、Worker subprocess
- Platforms: GPU、NPU
- Risk: High
- Current behavior: 每个进程执行环境检查、设置 ModelRunner 默认值并调用 `re_apply_patches()`。
- Ordinary request impact: 即使只运行普通请求，也可能安装全部 GR Beam Patch。
- Removal criteria: 激活计划能够按 capability、platform 和 process role 精确选择 Patch。

### P01 — CUSTOM Attention Selector Compatibility

- ID: `GR-PATCH-001`
- Source: `vllm_gr/patch.py`
- Target: `vllm.v1.attention.selector._cached_get_attn_backend`
- Mutation: private cached function replacement
- Required when: NPU 上显式请求 CUSTOM Beam Attention
- Risk: Critical
- Ordinary request impact: 全局 selector 被替换，普通请求也经过 wrapper。
- Planned replacement: PR #166

依赖：

- `_cached_get_attn_backend` 的签名和缓存语义；
- `AttentionBackendEnum.CUSTOM.is_overridden()`；
- 当前 vLLM config context；
- KV Cache layout 全局状态；
- vLLM-Ascend 清除非 `FLASH_ATTN` backend intent 的行为。

上游核验确认：vLLM-Ascend 会把非 `FLASH_ATTN` 的显式 backend 重置为 `None`，且 `NPUPlatform.get_attn_backend_cls()` 不会因为 CUSTOM registry 已注册而返回 GR Backend。因此当前 NPU compatibility bridge 有真实行为依据，但不应对所有平台无条件安装。

### P02 — NPUWorker Initialization Hook

- ID: `GR-PATCH-002`
- Target: `vllm_ascend.worker.worker.NPUWorker.init_device`
- Mutation: method wrapper
- Process role: NPU Worker
- Risk: High
- Current behavior: 在 NPU ModelRunner 创建前调用全量 `re_apply_patches()`。
- Removal criteria: Worker 只安装所需的 NPU compatibility，不重新运行全部 Patch。

`init_device` 名称不是 private，但它属于 vLLM-Ascend Worker 内部初始化生命周期，应分类为 `internal/unstable lifecycle API`。

### P03 — FlatLogprobs Fast Append Override

- ID: `GR-PATCH-003`
- Target: `vllm.logprobs.FlatLogprobs.append_fast`
- Mutation: existing method replacement
- Risk: Medium
- Owner: Beam Logprobs

修正：vLLM 0.22.1 已定义 `append_fast()`。GR 替换的是现有实现，不是新增 API。必须验证：

- 签名一致；
- start/end index 一致；
- token/logprob/rank/decoded token 写入一致；
- 空输入和 iterable 行为一致。

### P04 — OpenAI Beam Serving Behavior Override

- ID: `GR-PATCH-004`
- Targets:
  - `OpenAIServing.beam_search`
  - `ChatCompletionRequest.to_beam_search_params`
- Mutation: existing method replacement
- Process role: API Server
- Risk: High
- Planned replacement: W5 shared Beam coordinator and OpenAI adapter

修正：vLLM 0.22.1 中 `OpenAIServing` 已通过 `BeamSearchOnlineMixin` 提供 `beam_search()`，`ChatCompletionRequest` 也已有 `to_beam_search_params()`。GR 覆盖的是上游自带 Beam 行为，而不是新增 API。

该覆盖可能改变：

- 请求粒度；
- grouped-beam transport；
- logprobs 数量；
- EOS 和 Length Penalty；
- request ID；
- 输出重构。

### P05 — EngineArgs and Configuration Override

- ID: `GR-PATCH-005`
- Targets:
  - `EngineArgs.add_cli_args`
  - `EngineArgs.create_engine_config`
  - `EngineArgs.from_cli_args`
- Mutation: method replacement + dynamic state
- Risk: High
- Ordinary request impact: 所有 EngineArgs 配置创建都会经过 GR wrapper。

该 Patch 混合：

1. `--catalog-path` 注册；
2. GR 字段写入 `VllmConfig.additional_config`；
3. NPU block size 和 CUSTOM backend intent 修正。

修正：三个目标均真实存在，但 descriptor 不同：

- `add_cli_args`: staticmethod；
- `from_cli_args`: classmethod；
- `create_engine_config`: instance method。

当前实现依赖 `EngineArgs.from_cli_args.__func__`，因此必须增加 descriptor/signature contract test。

### P06 — OpenAIServingModels Constructor Override

- ID: `GR-PATCH-006`
- Target: `OpenAIServingModels.__init__`
- Mutation: constructor replacement
- Risk: High
- Purpose: 注入 Catalog 状态
- Ordinary request impact: 所有 OpenAI serving models 实例都新增 `catalog`。
- Removal criteria: Catalog 由 GR-owned service 注入，不替换上游构造函数。

### P07 — EngineCore Client and AsyncLLM Extension

- ID: `GR-PATCH-007`
- Targets: AsyncMPClient、SyncMPClient、InprocClient、AsyncLLM 的多个方法
- Purpose:
  - ADD_BATCH；
  - BEAM_REQUEST_STEP_UPDATE；
  - Beam output registration；
  - DP route tracking。
- Risk: Critical

主要内部依赖：

- `_send_input`；
- `_ensure_output_queue_task`；
- `_ensure_stats_update_task`；
- `core_engines`；
- `reqs_in_flight`；
- `first_req_send_socket`；
- `engines_running`；
- `current_wave`。

这些状态均由上游请求路由与完成清理直接使用，不是稳定扩展接口。

### P08 — EngineCoreRequestType Wire Enum Extension

- ID: `GR-PATCH-008`
- Target: `EngineCoreRequestType`
- Mutation: Python Enum private state mutation
- Added wire values:
  - `ADD_BATCH = b"\x06"`
  - `BEAM_REQUEST_STEP_UPDATE = b"\x07"`
- Risk: Critical

vLLM 0.22.1 当前使用 `0x00`–`0x05`，所以 `0x06` 和 `0x07` 暂未冲突。但 GR 依赖：

- `_value2member_map_`；
- `_member_map_`；
- `_member_names_`；
- `_name_`；
- `_value_`。

当前 wire value 没有冲突，不代表运行时 Enum 扩展是稳定方案。

### P09 — EngineCore Lifecycle, Socket Loop and Dispatch

- ID: `GR-PATCH-009`
- Targets:
  - `EngineCore.__init__`
  - `EngineCoreProc.__init__`
  - `EngineCoreProc.process_input_sockets`
  - `EngineCoreProc.run_engine_core`
  - Beam request handlers
- Risk: Critical

上游 `process_input_sockets()` 固定处理：

- ZMQ socket 和 READY handshake；
- coordinator；
- Tensor IPC；
- Msgpack decoder；
- request type decode；
- ADD 预处理；
- ABORT 双队列；
- input queue。

GR 为增加两种 wire message 复制并替换整个循环，构成强版本耦合。

### P10 — Scheduler Schedule Override

- ID: `GR-PATCH-010`
- Target: `Scheduler.schedule`
- Mutation: hot-path method replacement/wrapper
- Risk: Critical
- Behavior:
  - 临时替换 `kv_cache_manager.get_computed_blocks`；
  - 为 Beam Request 构建 `beam_data`；
  - 向 `SchedulerOutput` 动态增加字段。

依赖：

- `Scheduler.requests`；
- KVCacheManager 生命周期；
- `num_scheduled_tokens`；
- SchedulerOutput 可动态附加属性。

`SchedulerOutput` 当前是无 slots dataclass，因此动态字段可运行，但这些字段不是上游声明 contract。

### P11 — GPU ModelRunner Execution Override

- ID: `GR-PATCH-011`
- Targets:
  - `GPUModelRunner.execute_model`
  - `GPUModelRunner._prepare_inputs`
  - `GPUModelRunner._bookkeeping_sync`
- Risk: Critical

上游核验：GPU `_prepare_inputs()` 返回 2-tuple；GPU `_bookkeeping_sync()` 返回 7-tuple。GR 依赖这些私有返回结构以及 InputBatch、SamplingMetadata、logprobs tensor 的内部组织。

### P12 — NPU ModelRunner Execution Override

- ID: `GR-PATCH-012`
- Targets:
  - `NPUModelRunner.execute_model`
  - `NPUModelRunner._prepare_inputs`
  - `NPUModelRunner._bookkeeping_sync`
- Risk: Critical

上游核验：NPU `_prepare_inputs()` 返回 4-tuple；NPU `_bookkeeping_sync()` 多一个 `spec_decode_metadata` 参数并返回 6-tuple。GPU/NPU 必须作为两个独立 Patch 单元管理。

### P13 — CUSTOM Attention Backend Registration

- ID: `GR-PATCH-013`
- Mechanism: `register_backend(AttentionBackendEnum.CUSTOM)`
- Mutation: global registry override
- Risk: High

修正：`register_backend()` 和 `AttentionBackendEnum.CUSTOM` 是 vLLM 正式支持的扩展 API，不应归为私有 API。

风险来源是：

- CUSTOM 是单个全局 override 槽；
- 后注册者可能覆盖先注册者；
- Plugin 加载顺序决定最终 owner；
- 缺少 GR-specific backend identity。

### P14 — LMCache Adapter Override

- ID: `GR-PATCH-014`
- Targets:
  - `RequestTracker.from_new_request`
  - `ReqMeta.from_request_tracker`
  - `ReqMeta.__annotations__`
  - `LMCacheConnectorV1Impl.start_load_kv`
  - `save_kv_layer`
  - `wait_for_save`
- Risk: Critical

主要依赖：

- `tmp_disagg_tracker`；
- `_parent`；
- `_parent._get_connector_metadata()`；
- connector metadata requests；
- `slot_mapping` 和 `load_spec` 语义。

本轮只核验了 vLLM 和 vLLM-Ascend，LMCache 条目仍需按实际安装版本单独验证。

```text
VLLM_GR_LMCACHE_PATCH

```

### Import-order assumptions

- general plugin 在 Main、EngineCore 和 Worker 中都会加载；
- spawn 子进程不会继承父进程 Monkey Patch；
- NPUWorker compatibility 必须在 ModelRunner 创建前生效；
- BeamAttentionBackend import 会修改 CUSTOM registry；
- Benchmark module 是否已加载决定是否需要改写 `sys.modules` 引用。

## 10. 六项分类修正摘要

1. `FlatLogprobs.append_fast` 是现有方法覆盖，不是新增方法。
2. OpenAI Beam 是覆盖上游已有 Beam 行为，不是新增 API，风险提升为 High。
3. CUSTOM registry 是正式扩展 API；风险来自进程级单槽所有权。
4. `_all_token_ids` 有只读 `all_token_ids` 替代；`_block_hasher` 仍为私有依赖。
5. `NPUWorker.init_device` 应分类为 internal/unstable lifecycle API。
6. EngineArgs Patch 依赖 staticmethod/classmethod/instance method 的 descriptor 形态。

## 12. Acceptance Criteria

W1.2 完成时应满足：

1. 所有生产运行时 Patch 有唯一 ID；
2. Benchmark-only Patch 与生产 Patch 分离；
3. 每个 Patch 记录 source、target、process role、platform 和 required condition；
4. 每个 Patch 明确普通请求影响；
5. 每个 Patch 明确幂等、恢复和失败行为；
6. 私有、内部和正式扩展 API 被准确分类；
7. Critical dependency 有 contract test 或明确缺口；
8. 每个 Patch 有 owner 和 removal criteria；
9. Open PR 只作为 planned replacement，不与 current baseline 混淆；
10. 新增未经登记的 Patch 后续可被 CI 检测；
11. 本任务不改变任何生产算法或运行时行为。
